# Jouw testronde (gebundeld)

Alles wat een mens moet doen of goedkeuren, per story. Bouwers vullen dit aan; de lead bundelt het tot één testronde.

| Story | Wat | Hoe testen | Nodig |
|---|---|---|---|
| HZW-001 | Goedkeuring repo-structuur en README (fundament) | `pnpm install && pnpm lint && pnpm typecheck && pnpm test && pnpm test:e2e`; README lezen. Na push: Actions-tab, workflow `workspace-app` moet groen zijn | Niets; de workflow staat in de git-root (`.github/workflows/workspace-app.yml`) en draait pas na push (de lead pusht) |
| HZW-006 | Hoofdsleutel voor tokenversleuteling aanmaken en als secret zetten | `openssl rand -base64 32` als `HZ_TOKEN_KEY` in de server-secrets; de API weigert in productie te starten zonder (`apps/api/test/api.test.ts`, configuratie) | Toegang tot de secret-opslag (Coolify of sops/age) |
| HZW-020 | Rollen op de productie-Postgres: runtime-rol `hz_app`, de app-login en de pg-boss-login | Als beheerder: `psql -v migrator=<migratierol> -f packages/db/sql/bootstrap-roles.sql`, dan `psql -v login=hz_app_login -v password="$(openssl rand -base64 24)" -f packages/db/sql/app-login.sql` (LOGIN NOINHERIT, lid van alleen `hz_app`; het script weigert als hij ergens eigenaar van is). Die login als `DATABASE_URL` van api en worker; de migratierol (of een eigen login die alleen eigenaar is van schema `pgboss`) als `HZ_BOSS_DATABASE_URL` van de worker. Controle: api en worker starten met `NODE_ENV=production` zonder `UnsafeAppLoginError`, en `pnpm --filter @hz/db test` is groen. Lokaal en in CI is dit al gedaan (wachtwoord `hz_app_login`, alleen voor tests) | Een databasebeheerder (superuser of CREATEROLE) op de productie-Postgres; wachtwoord van de app-login in de secret-opslag |
| HZW-020 | Goedkeuring: datamodel-schets klopt met het prototype | README, "Database en rij-beveiliging" en "Import uit het prototype": tabel per collectie van het prototype (commitments, itemstate, briefings, processed, weekdoelen, contextcollecties) en waar die heen gaat; `packages/db/src/schema.ts` | Robert (en de developer) leest het na; 15 minuten |
| HZW-020 | Goedkeuring auth-functies samen met het auth-stuk (E1) | README, "Inloggen en de auth-bibliotheek": de adapter van Better Auth/Auth.js roept `auth_*`-functies aan, geen SELECT op users/sessions; `pnpm --filter @hz/db test` (auth.test.ts) | Afstemming met de bouwer van E1 bij het samenvoegen |
| HZW-021 | Export maken van de artifact-opslag van het prototype | In Claude met de artifact-tools alle documenten van de collecties `commitments`, `itemstate`, `briefings` (en `processed`/`weekdoelen` als die bestaan; de contextcollecties mogen mee) van het prototype-artifact lezen en als `{"collections": {…}}` wegschrijven naar een map buiten de repo (vorm: README, "Import uit het prototype"). Nooit in Git | Toegang tot het prototype-artifact van Robert |
| HZW-021 | Import draaien voor Robert en de tracker terugzien (goedkeuring) | `DATABASE_URL=<app-login-url> pnpm --filter @hz/db import:prototype -- --export <pad> --email robert@homezero.nl --proef`; klopt het verslag, dan zonder `--proef`; nog een keer draaien moet alles `ongewijzigd` geven. Daarna `HZ_STORE=db DATABASE_URL=… pnpm dev` en in Tracker/Dagstart de toezeggingen, weekdoelen, briefing en vastgezette zoekopdrachten terugzien | De export hierboven; een database met de migraties (lokaal of server) |
| HZW-040/041 | Goedkeuring schil en Dagstart naast de lat | `HZ_CONTEXT_EXPORT=<export> pnpm bar -- --modes demo,context && HZ_CONTEXT_EXPORT=<export> pnpm shot -- --modes demo,context && node tools/compare.mjs --blind`, open `.local/compare/index.html` | Een export van de contextlaag (alleen runtime) |
