# Jouw testronde (gebundeld)

Alles wat een mens moet doen of goedkeuren, per story. Bouwers vullen dit aan; de lead bundelt het tot één testronde.

| Story | Wat | Hoe testen | Nodig |
|---|---|---|---|
| HZW-001 | Goedkeuring repo-structuur en README (fundament) | `pnpm install && pnpm lint && pnpm typecheck && pnpm test && pnpm test:e2e`; README lezen. Na push: Actions-tab, workflow `workspace-app` moet groen zijn | Niets; de workflow staat in de git-root (`.github/workflows/workspace-app.yml`) en draait pas na push (de lead pusht) |
| HZW-006 | Hoofdsleutel voor tokenversleuteling aanmaken en als secret zetten | `openssl rand -base64 32` als `HZ_TOKEN_KEY` in de server-secrets; de API weigert in productie te starten zonder (`apps/api/test/api.test.ts`, configuratie) | Toegang tot de secret-opslag (Coolify of sops/age) |
| HZW-020 | Rollen op de productie-Postgres: runtime-rol `hz_app` en een aparte login voor de app | Als beheerder: `psql -v migrator=<migratierol> -f packages/db/sql/bootstrap-roles.sql`; daarna `CREATE ROLE hz_app_login LOGIN PASSWORD '…' NOINHERIT IN ROLE hz_app` (lid van alleen `hz_app`, eigenaar van niets) en die als `DATABASE_URL` van de api (de worker maakt met pg-boss een eigen schema aan en draait daarom met de migratierol; zijn queries op app-tabellen lopen via withUser als `hz_app`). Controle: `select rolsuper, rolbypassrls from pg_roles where rolname = current_user` geeft `f, f` en `pnpm --filter @hz/db test` is groen. Lokaal is dit al gedaan (hz_dev lid van hz_app) | Een databasebeheerder (superuser of CREATEROLE) op de productie-Postgres |
| HZW-040/041 | Goedkeuring schil en Dagstart naast de lat | `HZ_CONTEXT_EXPORT=<export> pnpm bar -- --modes demo,context && HZ_CONTEXT_EXPORT=<export> pnpm shot -- --modes demo,context && node tools/compare.mjs --blind`, open `.local/compare/index.html` | Een export van de contextlaag (alleen runtime) |
| HZW-010 | Google OAuth-client (type Intern) aanmaken en Robert laten inloggen; een privé-account moet geweigerd worden (goedkeuring) | Google Cloud (het project dat ook voor Taken gebruikt wordt, keuze 06): OAuth-toestemmingsscherm type **Intern**, scopes `openid email profile`; client type Web met redirect-URI's `https://<host>/api/auth/callback/google` en `https://<host>/api/connections/{google_tasks,calendar,gmail}/callback`; Tasks-, Calendar- en Gmail-API aanzetten. Secrets `HZ_GOOGLE_CLIENT_ID`, `HZ_GOOGLE_CLIENT_SECRET`, `HZ_AUTH_SECRET` (`openssl rand -base64 32`), `HZ_PUBLIC_URL=https://<host>`. Dan: Robert logt in (komt in `/welkom`), een @gmail.com-account krijgt "Dit account hoort niet bij HomeZero". Lokaal zonder Google: `pnpm test:e2e -- e2e/e1.spec.ts` (nep-uitgever) | Google Workspace-beheerder (Intern-scherm), toegang tot de server-secrets |
| HZW-011 | Goedkeuring: uitloggen werkt op alle apparaten | Log in op laptop en telefoon, Instellingen → Apparaten → "Overal uitloggen"; de telefoon toont daarna het inlogscherm. Tests: `apps/api/test/auth.test.ts` (verlopen, ingetrokken, gestolen sessie, verlengen) en `e2e/e1.spec.ts` | Twee apparaten met een @homezero.nl-account |
| HZW-012 | Teamlijst vullen en goedkeuren | Zet de collega's op de uitnodigingslijst: in de app via Instellingen → Team (als Robert), of `HZ_ALLOWLIST=a@homezero.nl,b@homezero.nl`. Beheerders: robert@homezero.nl staat vast als admin op de lijst (migratie); een tweede beheerder via Team (rol beheerder) of als databasebeheerder `psql "$MIGRATIE_URL" -v email=… -v rol=admin -f packages/db/sql/e1-beheerder.sql` (`HZ_ADMIN_EMAILS` telt alleen zonder Postgres). Controleer de ledenlijst na de eerste logins; blokkeren logt iemand overal uit | Lijst met e-mailadressen van het team |
| HZW-013 | Goedkeuring: een collega (niet Robert) doorloopt de wizard zonder uitleg | Na de eerste login opent `/welkom` vanzelf; overslaan en "Later afmaken" (verder via de zijbalk of `g w`). Zonder echte koppelingen proberen: `pnpm --filter @hz/fake-oauth start` en de API starten met de omgeving uit `e2e/e1-env.ts` (`E1_API_ENV`) | Een collega, en voor echte koppelingen de apps van HZW-014 |
| HZW-014 | Slack-app (intern), Atlassian 3LO-app en GitHub App aanmaken; intrekken echt controleren bij Google en Slack (goedkeuring) | **Slack**: interne app in de HomeZero-workspace, alleen *user* scopes zoals in `PROVIDER_CATALOG.slack.scopes` (`packages/shared/src/auth.ts`), redirect `https://<host>/api/connections/slack/callback`, secrets `HZ_SLACK_CLIENT_ID/SECRET`; goedkeuring door een Slack-beheerder (open vraag K3). **Atlassian**: developer.atlassian.com → OAuth 2.0 (3LO), scopes `read:jira-work read:jira-user` (+ `offline_access`), callback `https://<host>/api/connections/jira/callback`, `HZ_ATLASSIAN_CLIENT_ID/SECRET`. **GitHub App** op HomeZeroTech: Contents lezen (HomeZero-context), Contents lezen/schrijven (Persoonlijk-repo's), Metadata lezen, "Request user authorization (OAuth)", callback `https://<host>/api/connections/github/callback`, verlopende user-tokens aan, `HZ_GITHUB_CLIENT_ID/SECRET`, app installeren op de repo's. Test: koppel elke bron, trek in, en kijk bij myaccount.google.com/permissions en in Slack (Apps beheren) dat de app weg is. Google trekt per app in, niet per bron: de app roept het intrek-endpoint pas aan bij de laatste Google-bron (Taken, Agenda, Gmail); daarvoor wist hij alleen het token en zegt dat. Controleer dus: Gmail ontkoppelen laat Taken werken en de app staat nog bij Google; na de laatste Google-bron is hij weg. Atlassian heeft geen intrek-API: daar zelf verwijderen via id.atlassian.com → Connected apps | Beheerrechten in Slack, Atlassian en de GitHub-organisatie; toegang tot de server-secrets |
| HZW-010/052 | Besluit S3 bevestigen: Auth.js (gekozen) in plaats van Better Auth | Auth.js is gekozen omdat de adapter de sessies op de fundamenttabellen houdt (alleen een tokenhash, RLS). Gevolg: voor de OAuth 2.1-server van de MCP (HZW-052) is een losse oplossing nodig (bv. `oidc-provider` of de auth-helpers van de MCP-SDK); zie `apps/api/src/auth/authjs.ts` | Akkoord van Robert en de developer |
| HZW-010/020 | Samenvoegen met stuk E2: migratievolgorde | Zet E2's migraties (0005–0009) vóór die van E1 en nummer E1 erna (bv. 0010_e1_auth, 0011_e1_auth_compat); `0006_e1_auth_compat.sql` slaat dan alles over (mag ook weg). Controle: `pnpm --filter @hz/api test` (39 tests in `auth.test.ts`, ook het blok Postgres) groen; zo lokaal al gedraaid met E2's migraties | De samenvoeger (lead) |
